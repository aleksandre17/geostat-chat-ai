# ADR-011: RAG derivation architecture — corpus is the single source of truth

- **Status:** Accepted
- **Date:** 2026-05-24
- **Plan:** [docs/plan/PROJECT-PLAN.md](../plan/PROJECT-PLAN.md) Phase 8 · [RAG-DERIVATION-ARCHITECTURE.md](../plan/RAG-DERIVATION-ARCHITECTURE.md) · [approved](../plan/approved/README.md) D-25, D-26

## Context

Through 2026-05-24 the chat catalog (topics, portal URLs, specific links, keywords, locale pairs) lived as hand-edited YAML — primarily `apps/backend/src/main/resources/catalog/topics.yaml` (2364 lines) plus `specific-links.yaml` and `news-categories.yaml`. The original RAG-U01 proposal was to migrate this YAML *as-is* into Postgres tables.

Owner senior review (transcripts: derivation-architecture discussion, 2026-05-24) raised the architectural question: **should the system itself derive this knowledge from the corpus rather than store curated rows that still require manual maintenance?**

This affects every recurring catalog gap — new pages added to geostat.ge are invisible until a human edits YAML; English/Georgian pairs drift; "official portal" status is editorial, not data-driven; keywords are a frozen snapshot.

## Decision

Adopt a **derivation architecture**. The corpus (Postgres `ingestion.document` + Qdrant vectors) is the single source of truth. Topics, portals, specific links, and keywords are **computed** from the corpus, not authored alongside it.

### 1. Four layers + online query layer

| Layer | Responsibility | Mutability |
|---|---|---|
| **L1 Corpus** | Crawled documents, chunks, embeddings | append-only by ingestion |
| **L2 Enrichment** | Per-document derived fields (summary, keywords, entities, locale pair, authority, page_kind, topic cluster, multi-vector index) | regenerated by derivers |
| **L3 Catalog views** | Materialized views for portal links, specific links, topic keywords | refreshed nightly |
| **L4 Curation overlay** | Tiny human override layer (≤50 rows, action ∈ boost/demote/exclude/pin_as_portal/rename_topic) | small CRUD UI |
| **L5 Online query** | Query understanding → hybrid retrieval → rerank → confidence → response | runtime per request |

### 2. Approved derivers (RAG-U01a..h)

```text
SummaryDeriver        Gemini 2-3 sentence summary ka/en          per-doc async
KeywordDeriver        YAKE Java port, top-15 per language        per-doc async
EntityDeriver         Gemini few-shot (INDICATOR/YEAR/REGION/..) per-doc async
LocalePairDeriver     URL pattern + embedding cosine             per-doc async
AuthorityDeriver      JGraphT PageRank + recency                 nightly batch
PageKindClassifier    closed-set (portal/dataset/report/news/    per-doc async
                       faq/navigation/unknown)
TopicMiner            Smile k-means on summary embeddings +      nightly batch
                       Gemini cluster label (admin-approved)
DocumentVectorWriter  Qdrant named vectors (title, summary)      per-doc async
```

### 3. Approved query pipeline (RAG-U07–U11)

```text
SpellFixer (SymSpell) → Normalizer → IntentClassifier (Gemini)
  → EntityExtractor → QueryExpander (terminology-overlay.yaml + LLM)
QueryEmbeddingStrategy: Direct + HyDE + MultiQuery
HybridRetriever: Qdrant(summary, title, body) + Postgres tsvector
  → RRF fusion (k=60) → CrossEncoderReranker → MMRDiversifier
RetrievalConfidence: HIGH / MEDIUM / LOW / NONE
ResponseRouter: answer | answer+suggest | clarify | refuse
```

### 4. Eval gate (mandatory)

`ingestion.evaluation_query` extended with `expected_intent`, `expected_entities`, `expected_topic`, `difficulty`, `source`. Target golden set 150–300 questions. Nightly + per-PR `ops/ci/run-eval.py` computes hit@1, hit@5, MRR, NDCG@10, intent_accuracy, entity_F1, mean_response_ms. PR fails on >5% regression on any metric. Rollout of any derivation feature flag requires `hit@5 ≥ baseline`.

### 5. Free packages adopted (benefit gate per ADR-010)

| Package | Reason |
|---|---|
| **JGraphT** | PageRank for authority graph; mature Apache 2.0; replaces hand-coded heuristic |
| **Smile** | k-means clustering for topic mining; same author quality as Weka, Apache 2.0 |
| **YAKE Java port** | language-agnostic keyword extraction; lighter than KeyBERT, no Python sidecar |
| **SymSpell Java** | typo correction with custom ka/en dictionaries; MIT |
| Postgres tsvector | already present; promoted from naive `simple` config to BM25 ranker |
| Qdrant named vectors | already supported; multi-vector enables summary/title/body retrieval cascade |

Rejected for P1/P2: Stanza Georgian, BERTopic, KeyBERT (Python sidecar overhead not justified before eval shows Java fallback gap); Apache AGE / Neo4j (knowledge graph deferred to P4 when corpus > 50K docs).

### 6. What is removed (zero-gap)

After eval gate passes:

- `apps/backend/src/main/resources/catalog/topics.yaml` (2364 lines) — DELETED
- `YamlTopicCatalog`, `TopicCatalogLoader`, `SpecificLinkLoader`, `NewsCategoryLoader` — DELETED
- `CatalogRagLinkMerger` simplified to read `mv_portal_link` + `mv_specific_link`

What stays:

- `topic-style.yaml` (~80 lines) — presentation only (icon, color per page_kind)
- `terminology-overlay.yaml` (≤40 entries) — small synonym graph (CPI ↔ ფასების ინდექსი)

### 7. Curation overlay scope

Owner can override derivation only via `ingestion.curation_override`:

- `boost` / `demote` (multiplier on `score_boost`)
- `exclude` (drop from retrieval)
- `pin_as_portal` (force `mv_portal_link` row)
- `rename_topic` (override `topic_cluster.label_*`)

`reason` mandatory; default TTL 90 days; budget ≤50 rows. If exceeded, signals deriver problem to fix upstream.

### 8. Approved decisions (D-25, D-26)

- **D-25 — Derivation architecture adopted.** Corpus is single source of truth; topics/portals/specific links derived; YAML catalog deprecated.
- **D-26 — Curation overlay budget ≤50 rows; TTL 90d default; reason mandatory.** Overlay is exception layer, not authoring surface.

## Consequences

**Positive**

- Self-extending: new pages auto-categorized, no YAML edits.
- Locale parity: pairing computed, not authored.
- Authority signal: derived from in-link graph.
- Topic discovery: clustering reveals real corpus structure.
- Maintenance: near-zero (curation overlay is exception only).
- Audit: per-field `enrichment_run` provenance with model_version.
- Graceful degradation: failed deriver leaves field NULL; system still works on remaining signals.

**Negative**

- Cold start: empty corpus → empty catalog. Mitigation: ≤10 `pin_as_portal` overrides bootstrap day-1.
- Approval queue: unapproved `topic_cluster` rows need owner review before mv_portal_link uses them. Mitigation: admin tab in P3.
- Cost: Gemini calls for summary/entities/page_kind ≈ ~$0.05 per 1K docs flash-lite. Acceptable per ADR-010 D-16.
- Migration risk: feature-flagged dual path; eval gate before YAML deletion.

## Alternatives considered

| Alternative | Rejected because |
|---|---|
| Keep YAML, add admin UI to edit it | Doesn't self-extend; manual maintenance forever |
| Migrate YAML rows directly to DB tables | Same problem moved one storage hop; no derivation |
| Pure emergent (no curation overlay) | Cold-start fragile; no escape hatch for known data quality issues |
| Hand-curated knowledge graph (Neo4j/AGE) day-1 | Premature; corpus too small; derivation must succeed first |
| Hand-tuned BM25 + dense per query class | Doesn't scale; query-class taxonomy itself becomes manual catalog |
| LLM at retrieval time (no precompute) | Latency + cost prohibitive on every query |
